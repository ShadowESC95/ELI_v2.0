# Test Coverage — Methodology, Measurement, and Exclusions

This document describes how ELI's automated test coverage is measured, how to
reproduce the figure, and which code is excluded from the line-coverage metric
**with a stated, auditable rationale**. It is written for external review
(security, privacy/GDPR, and procurement audits).

Coverage is **measured, reproducible, and honest** — no line is counted that a
test does not genuinely execute, and no exclusion is undocumented.

---

## 1. How to reproduce the number

```bash
bash scripts/coverage_full.sh
```

Outputs `artifacts/coverage_report.txt` (text, per-file) and
`artifacts/coverage_html/index.html` (browsable, line-by-line). Configuration is
in `.coveragerc`. The figure (§6) is regenerated by this command on any checkout.

## 2. Why coverage is measured in four lanes

`scripts/coverage_full.sh` runs four passes and combines them (`coverage combine`):

| Lane | Deps | Exercises | Invocation |
|------|------|-----------|------------|
| 1. Full suite | real libraries, inside the sandbox `tests/conftest.py` sets up | everything under `tests/` | `pytest tests/` |
| 2. Web server | **real FastAPI**, in the same sandbox | `api/server.py` auth/RBAC + endpoints | `pytest tests/test_api_server.py` |
| 3. Live engine | **real GGUF model** (`ELI_COVERAGE_MODEL`, default `models/tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf`; skipped when absent) | full pipeline: router → agent bus → grounding → GGUF → governance | `ELI_MODEL_PATH=<model> pytest tests/test_engine_integration_live.py` |
| 4. Offscreen GUI | **real PySide6**, `QT_QPA_PLATFORM=offscreen` | the tab widgets' construction, layout and wiring | `pytest tests/test_gui_offscreen.py` |

The lanes date from when the shared conftest replaced the heavy runtime libraries
(`pydantic`, `llama_cpp`, `torch`, `faiss`, `PySide6` and others) with mocks: under it
the real web server could not be imported, a model could not be loaded and the GUI
could not be built, so those three files skip themselves when such an import fails and
were measured on lanes of their own. Since v2.5.22 the suite loads the real libraries
and is sandboxed instead: CPU only (`CUDA_VISIBLE_DEVICES=""`, `ELI_FORCE_CPU=1`),
offscreen Qt, no display, desktop session bus, sound server or network, and every store
redirected under `artifacts/_pytest/`. Lane 1 therefore runs those files as well — the
live-engine tests whenever a chat GGUF is in `models/` (the smallest one, or
`ELI_MODEL_PATH`). Lanes 2–4 run them again in that same sandbox (they used to skip the
shared conftest, which left the stores and the audit chain pointing at the checkout's
`artifacts/db`, and lane 3 without its `small_chat_model` fixture); lane 3 takes the model
`ELI_COVERAGE_MODEL` names. A lane that fails is named at the end and the script exits 1,
with the combined report written all the same.

## 3. Coverage discipline (no gamed tests)

Assertions target **behaviour the code guarantees**, not incidental line
execution. In particular, the live-model lane asserts *structure* — routed
action, non-empty governed reply, result-shape contract, session continuity,
safe handling of empty/garbage input — and never an exact model string (which
would couple the test to a specific model's output rather than to the code).

## 4. Security- and privacy-critical coverage

The paths most relevant to a security/GDPR review are covered directly and
deeply:

- **Authentication / RBAC** (`api/server.py`): bearer parsing, role hierarchy,
  loopback detection, every `_resolve_principal` branch (tokenless owner /
  correct token / wrong token → fail-closed / no-config → deny /
  `ELI_LOOPBACK_ADMIN=0`), the Host-name check against DNS rebinding (a foreign
  name gets no tokenless grant; a token works by any name), and the live
  401/403/200 gate through the real dependency graph. RBAC end to end is in
  `tests/test_api_rbac.py`; the owner-only action gate (`authority_gate.check`
  and the executor's entry check) in `tests/test_mcp_server.py`.
- **Offline-by-default enforcement** (`eli/core/netguard`): the socket failsafe
  and egress recording are unit-tested.
- **Data isolation**: the shared conftest redirects every store into
  `artifacts/_pytest/`, and `tests/conftest.py::_assert_db_isolated` fails the run
  if the user, memory, agent, audit or capability-state database, the persona
  overlay, the notes or notebook folder or the world state resolves outside it — a test in the shared suite
  cannot touch real user data. Lanes 2–4 run without that conftest and redirect only
  `ELI_ARTIFACTS_DIR`, which does not move the databases (they follow `ELI_DATA_DIR`
  and the per-store variables), so in a source checkout what those tests record in the
  audit ledger can reach the checkout's own `artifacts/db/`.

## 5. Documented exclusions (justified, not hidden)

Some code cannot be executed in an automated, headless CI context. It is
**excluded from the line metric with rationale**, not faked. Besides `tests/`,
`build/`, `.venv/` and `__pycache__/`, `.coveragerc` omits only:

| Area | Statements | Why excluded from automated line coverage |
|------|-----------:|-------------------------------------------|
| Interactive desktop main window (`eli/gui/eli_pro_audio_gui_v2_0.py`, `EliMainWindow`) | 8,225 | Blocks on interactive display/device/audio init; full-window construction does not terminate headless. The tab widgets are measured on lane 4 and testable GUI *units* (pure helpers, small widgets) in lane 1; the interactive window is validated manually and via the run-book. |
| Module entry points (`*/__main__.py`: `eli/__main__.py`, `eli/setup/__main__.py`, the image engine's) | 85 | Each runs as its own process (`python -m …`); the tests that start one do so in a subprocess, which this measurement does not follow. |

Counted, not excluded: GPU/model-load internals beyond the live lane (the
CUDA/Metal/CPU-offload variants need the matching hardware) and hardware/OS device
I/O (real microphone, camera, speakers, window manager) stay in the denominator and
show as uncovered in a headless run, as does code that is merely untested —
excluding them would inflate the number.

These exclusions are standard and defensible: automated line coverage measures
**headless-executable logic**; the interactive window and hardware I/O are validated
by other means (manual test run-book, on-device acceptance).

## 6. Current measured figure

Regenerate with `scripts/coverage_full.sh`. The run writes
`artifacts/coverage_report.txt` (and `artifacts/coverage_html/`) on the machine that
ran it; runtime artifacts are not committed to git, so there is no committed figure.
Headline and per-file numbers are in that report, so the figure is always the
*measured* one, never a stale claim in prose.
